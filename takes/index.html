infobloxKentik deployment tool: two new takes

Three ways to answer "how is Kentik deployed for us?"

The current app starts from Kentik's reference design, and the SE fits it to the customer. These two takes start somewhere else. Take A starts from the customer's own network. Take B starts from the work that the customer's teams must do. Both keep the interactive diagram, and both use the same Kentik facts as the current app (from configurator/catalog.py).

Take A

Network Canvas

Draw their network. Kentik plans itself on top.

The SE draws the customer's real sites, devices, WAN links and clouds on a free canvas. The tool works out the rest, and it updates as you draw.

  • Agent placement, and the path that each kind of data takes
  • Lenses with moving data: flow, metrics, events, BGP, DNS, tests, cloud
  • Firewall rules for each firewall, and the telemetry load on each WAN link
  • Checks with one-click fixes, groups of similar sites (×120 stores)
  • Customer pack: interactive HTML, firewall CSV, agent build sheet, printed brief

Take B

Rollout Map

The deployment is a project. Show the customer how it goes live.

The design becomes a plan in waves. A transit map shows what is live after each wave, and each customer team gets its own list of tasks.

  • Transit map: each kind of data is a line into Kentik, each site a station
  • Timeline: play the rollout wave by wave, and see the coverage grow
  • Tasks for each team (network, security, server, cloud, DNS, Infoblox), made from the design
  • Proof of value or full rollout, with dates
  • Customer workbook: one HTML file in which the customer marks tasks as done
